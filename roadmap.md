# Attendly — план разработки MVP

Преподаватель ведёт список студентов одной учебной группы, отмечает посещаемость на каждой паре и смотрит сводку пропусков за выбранный период. Журнал открывается из консоли и сохраняет данные между запусками.

Для первой версии принимаем Python 3 и локальную базу SQLite через стандартный модуль `sqlite3`. Команды доступны через текстовое меню, запуск приложения — `python -m attendly`.

## 1. Подготовить консольное приложение и хранилище

- [x] Создать точку входа и меню с разделами «Студенты», «Посещаемость», «Статистика» и «Выход». Обрабатывать неизвестные пункты меню и позволять вернуться назад из каждого раздела.
- [ ] При первом запуске создать файл `attendly.db` в рабочей папке и таблицы `students` (ID, ФИО, активность), `lessons` (ID, дата, номер пары) и `attendance` (ID пары, ID студента, статус).
- [ ] Включить проверку внешних ключей SQLite. Ограничить статус двумя значениями — «присутствовал» и «отсутствовал». Обеспечить уникальность пары по дате и номеру, а отметки — по паре и студенту.

**Критерий готовности.** Первый запуск без файла базы создаёт его и открывает меню. Повторный запуск из той же папки использует существующую базу.

## 2. Реализовать CRUD для списка студентов

- [ ] Добавлять студента с непустым ФИО и автоматически присваивать ему ID. Показывать в списке ID и ФИО, чтобы можно было различать тёзок.
- [ ] Просматривать список активных студентов и изменять ФИО по ID. При неизвестном ID выводить понятное сообщение и возвращать пользователя в меню.
- [ ] Удалять студента без отметок. Студента с отметками переводить в архив, чтобы сохранить историю. Показывать архив отдельно от активного списка.

**Критерий готовности.** Можно добавить двух студентов с одинаковым ФИО, отредактировать одного по ID и удалить запись без отметок. При архивировании студента его отметки сохраняются в базе, а сам студент отображается в архиве.

## 3. Реализовать журнал посещаемости

- [ ] Принимать дату в формате `ГГГГ-ММ-ДД` и положительный номер пары. По этим данным открывать существующую пару или создавать новую при сохранении отметок.
- [ ] Для новой пары показывать активных студентов. Для существующей пары также показывать сохранённые отметки архивных студентов, чтобы преподаватель мог просмотреть или исправить историю.
- [ ] Ставить статус, менять его и снимать отметку. Строку без отметки показывать как «не отмечен». Повторное сохранение обновляет существующую отметку по тому же студенту и паре.
- [ ] Сохранять отметки за пару одной транзакцией. При ошибке записи отменять сохранение целиком и сообщать об ошибке в консоли.

**Критерий готовности.** Можно заполнить две пары за один день, перезапустить приложение, открыть каждую пару и исправить или снять отметку. При повторном открытии видны сохранённые изменения.

## 4. Добавить сводку по группе

- [ ] Запрашивать начальную и конечную даты периода и включать обе границы в расчёт. Если начальная дата позже конечной, просить ввести период повторно.
- [ ] Показывать по каждому активному студенту количество присутствий и пропусков за период. Включать архивных студентов, если у них есть отметки в выбранном периоде.
- [ ] Выводить общее число пропусков по группе. Считать пропуском каждую пару со статусом «отсутствовал». Строки «не отмечен» исключать из подсчёта.

**Критерий готовности.** Если за день у студента один пропуск, одно присутствие и одна пара без отметки, сводка за этот день показывает один пропуск и одно присутствие. После исправления пропуска на присутствие сводка показывает ноль пропусков и два присутствия.
